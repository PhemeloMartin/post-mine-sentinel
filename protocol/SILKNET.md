# SilkNet v1 — frame specification

SilkNet is the over-the-air protocol between S.P.I.D.E.R. sensor nodes, relaying nodes and anchor
gateways. It runs on LoRa (868 MHz, SF9 / 125 kHz / CR 4/5 by default) and is designed for:

* **Small frames**: 32 bytes for a detection, so a 1 % duty cycle still allows ~175 frames per hour.
* **Confidentiality + integrity**: AES-128-CCM (RFC 3610 / NIST SP 800-38C), 8-byte MIC.
* **Replay protection**: a strictly increasing 32-bit frame counter per node, verified at the ingest service.
* **Multi-hop**: relays may change the hop count without breaking authentication (the `flags` byte is excluded from the AAD).

## 1. Frame layout (big-endian)

| Offset | Size | Field | Notes |
|---|---|---|---|
| 0 | 1 | `ver_type` | high nibble = version (`1`), low nibble = frame type (table 2) |
| 1 | 1 | `flags` | bit0 ACK requested · bit1 relayed · bits2–4 hop count (0–7) · bits5–7 reserved (0). **Not authenticated** |
| 2 | 2 | `site_id` | site index within the national network |
| 4 | 2 | `node_id` | 1–239 spiders, 0xFF01–0xFF0F anchors |
| 6 | 4 | `frame_counter` | strictly increasing per node; never reused with the same key |
| 10 | *n* | `ciphertext` | AES-128-CCM encrypted payload |
| 10+*n* | 8 | `mic` | CCM authentication tag (M = 8) |

**AAD** = byte 0 ‖ bytes 2–9 (9 bytes). **Nonce** (13 bytes, L = 2):
`site_id(2) ‖ node_id(2) ‖ frame_counter(4) ‖ direction(1) ‖ 0x00000000(4)` where direction `0x00` = uplink, `0x01` = downlink.

## 2. Frame types

| Type | Name | Payload |
|---|---|---|
| 0 | `HEARTBEAT` | detection layout with class = 0, p = 0 |
| 1 | `DETECTION` | seismic window classified as a threat |
| 2 | `PIR` | passive-infrared trigger |
| 3 | `TAMPER` | accelerometer / enclosure tamper (last-gasp) |
| 4 | `BENIGN` | triggered window classified benign (negative evidence) |
| 5 | `ACK` | 0-byte payload, downlink |
| 6 | `BEACON` | routing beacon: ETX to gateway, parent id |

## 3. Detection payload (14 bytes)

| Offset | Size | Field | Encoding |
|---|---|---|---|
| 0 | 4 | `window_start` | Unix seconds (uint32) |
| 4 | 1 | `class_id` | 0 background · 1 footsteps · 2 digging · 3 machinery · 4 vehicle · 5 animal · 6 blast |
| 5 | 1 | `p_threat` | round(p × 255) |
| 6 | 1 | `snr_db` | int8, clamped to [−60, 120] |
| 7 | 2 | `arrival_ms` | first-arrival offset within the window (0–4000), GPS-PPS disciplined |
| 9 | 1 | `battery_pct` | 0–100 |
| 10 | 1 | `status` | bit0 tamper · bit1 low battery · bit2 RF jamming suspected · bit3 ADC saturation (blast or physical shock) |
| 11 | 3 | reserved | zero |

A detection frame is therefore 10 + 14 + 8 = **32 bytes** (time-on-air ≈ 246 ms at SF9/125 kHz).

## 4. Keys

* Each site has a 128-bit **site master key** held in Azure Key Vault (HSM-backed) and in the anchors' secure element (ATECC608B).
* Per-node keys are derived, so a captured node only exposes itself:
  `K_node = HMAC-SHA256(K_site, "silknet-v1" ‖ site_id ‖ node_id)[0:16]`.
* Firmware images are signed (Ed25519); nodes refuse unsigned OTA updates.
* **Never reuse a (key, nonce) pair**: the frame counter is persisted in RTC backup RAM + flash before transmission.

## 5. Receiver rules (ingest service)

1. Drop frames whose version ≠ 1 or whose length doesn't match the type.
2. Derive `K_node`, verify the CCM MIC. **Fail closed**: authentication failures are counted and dropped, never parsed.
3. Reject `frame_counter ≤ last_accepted[node]` (replay). Allow a sliding window of 32 for out-of-order multi-gateway duplicates, de-duplicated by `(site, node, counter)`.
4. Group votes by `(site, window_start)` for 2.5 s, then post one batch to the fusion API.

## 6. Conformance

`protocol/test-vectors.json` (generated by `protocol/gen_vectors.py` with the Python `cryptography`
reference implementation) contains AES-128 (FIPS-197), AES-CCM (RFC 3610 packet vector #1), key
derivation and complete SilkNet frames. The Go ingest service and the C++ firmware **must** pass
all vectors in CI.
